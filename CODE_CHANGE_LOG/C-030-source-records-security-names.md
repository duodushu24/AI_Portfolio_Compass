# C-030：导入资料管理与标的名称修改

## 实际修改

- 现有“导入数据”菜单增加“导入记录”抽屉，展示保存的持仓来源、资料时间、数量及详情；可停止/恢复核对、软删除/恢复。旧资料未保存导入时间时明确显示“未记录”，不假造文件名或原始文件备份。此入口管理已保存的持仓来源，不是全部操作的导入日志；标准起点与买卖仍在账户记账中维护。
- 起点读取与数据概览不再自动核对；抽屉内可逐条或批量主动核对。保留相同实际时点重放，明确区分一致、数量/成本差异、标的/单位未匹配及早于起点；未匹配不显示为零。统一已知代码前缀和类型标签，单位冲突可显式确认核对对应关系，不转换数量、不修改正式账目。完整来源含已删除/停用成员时不再据其推断未列出的资产为零。
- 已建档账户删除/恢复资料与停用核对不改起点、交易、现金或收益；未建档账户提示会影响待确认持仓。沿用 `PositionSnapshot.is_void`，仅新增 `reconciliation_data` JSON 保存核对状态/对应关系；SQLite 启动时增列，旧值默认空对象。本轮未对正式数据库运行迁移。
- 资产组合和账户持仓名称旁增加编辑入口，直接同步已有起点、成交、估值、来源记录中的名称字段。同一标的跨账户统一，不增加名称表、别名或展示名称列；代码、数量、价格、日期和收益保持不变。不调用金融事实纠错/基准校验，缺资料账户也可以改名。
- Excel/同步、标准起点确认及广发重建入口沿用已有名称，新标的的明确境内 XD 前缀在导入时清理；不批量改写历史账目。维护起点文件幂等签名，改名后重复导入不覆盖名称；其他账目纠错仍受原幂等保护。
- 改名失败保留弹窗错误信息；同账户重新读取时保留已有概览，防止写后刷新提前卸载编辑器。核对 POST 按只读请求处理，不触发全页写后刷新；历史账目抽屉排除资料时点之后的记录。

## 验证与限制

- `backend/tests/test_source_records_names.py` 共 15 项隔离检查通过：直接改名的跨账户/历史字段同步、数值与报价日期不变、非法名称、代码/类型匹配、单位冲突与显式对应、早于起点/未知标的、停用/删除/恢复、账户边界及事务回滚、缺失导入时间、后续导入保留名称、不自动核对、旧表增列、广发改名后再次导入及完整来源的缺席推断保护。均使用虚构内存 SQLite；接口验证为直接调用实际路由处理函数，不宣称 HTTP 传输验证。
- 一项既有标准起点 Excel 预览/原子确认/重复导入检查通过。其他既有测试尝试受到沙箱临时目录限制；直接运行旧广发联合导入测试还遇到“无独立报价却要求总资产为 500”的旧断言，本轮不扩大范围修改。新广发隔离用例核对现金、摊薄成本及改名后幂等，不宣称旧回归整组或全套测试通过。
