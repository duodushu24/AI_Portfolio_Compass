# C-010：持仓页面收敛、清仓收益率与规范历史录入

关联 [P-005](../issues/P-005-portfolio-return-history.md) 与唯一方案 [S-002](../issues/solutions/P-005/S-002-account-ledger-performance.md)。用户确认重启后名称问题已消失，本轮不修改名称逻辑；也不扩展资产类型或调用外部投资分析。

## 实际修改与关键选择

数据页按“数据管理 → 账户收益 → 账户记账”排列，同级标题使用一致字号；顶部规范持仓表复用 `AssetTable`，可包含已清仓、查看同一收益组件的标的详情。中间账户收益不再重复持仓，维护说明不依赖上下位置。已建档账户的数据接口返回当前及已清仓的同一账目投影，未建档来源界面保留；导入/保存后共享刷新版本，避免当前持仓更新而曲线或账目仍是旧结果。

重放账目累计每个持有阶段的卖出结转成本与已实现利润，完整卖出才保存派生阶段结果。清仓比例按阶段利润除以结转成本合计，包含分批买卖及费用；未知/零成本不计算百分比。再买入保留历次清仓，列表最近清仓收益率与累计已实现金额分别标注，详情有各阶段成本、收益额/率及时间。转托管没有虚构卖出，不沿用上一阶段清仓比例。

来源核对按快照日期重放相同时点的数量和平均成本，币种/单位同时定位，允许有限浮点来源舍入差。早于统计起点标未覆盖而非账目错误；完整快照可验证未列出的标的，部分导入不推断缺席即清仓。原来源只读，错误提醒显示日期及数量/成本双方。

新账户默认“从首笔交易开始”，设置交易前现金或零现金加首笔入金，首笔买入自动建立数量、成本与报价。成交价作为初始报价，费用计入平均成本；不把同一笔买入同时录成期初持仓，已有持仓仍可作为单独起点模式。账户界面改用“累计账户盈亏”和实际起点，不固定强调软件建档之后。

已有账户提供更早历史试算及保存接口。表单复用买卖/资金编辑器，记录先加入当前批次，试算后全部回滚；确认保存再用同一事务更新起点和事实、重放验证。核对原起点数量、已知成本、现金、负债和待确认事项，差异必须明确确认，不能用自动入金兜底。原起点保留为核对资料，原价格/汇率保留为日期观察，旧持仓不再次初始化。显式组合纳入日期保持，原默认随起点纳入的日期可前移。没有新增收益算法、数据库草稿表、版本哈希或历史格式解析器。

## 验证与限制

- 账目文件 30 项测试通过，覆盖基础平均成本/现金/净值、分批清仓/再买入、缺成本、同日期/起点前/完整与部分来源核对、首笔入金及历史试算回滚/差异确认/统一保存。收尾只运行涉及清仓/转托管的 4 项，通过；全项目测试未运行。
- 最终 `npm run build` 与 `tsc --noEmit` 通过，包含收尾表单按钮与共享刷新调整。既有大包和依赖弃用提示保留。沙箱临时目录、TestClient 与 Vite realpath 遇到环境限制，使用专用项目内临时目录与获准执行环境完成验证，不修改环境依赖。
- 隔离 Edge/FastAPI/Vite 与虚构 SQLite 验证页面顺序、标题字号、单份持仓、清仓收益率/历次详情、旧快照无误报、历史试算不落库→保存→刷新持久化，以及零现金→首笔入金→买入→价格更新。收尾直接核对一次更新同步刷新持仓、账户收益和账目；无 JS 异常。合成截图另作视觉核对，均在忽略目录。
- 真实数据库、账户期初和交易未自动更改，私有信息未写入本记录或测试。尚未在用户真实账目验收；历史数据由用户逐段录入。历史首笔报价与观察点不等同于完整每日行情，历史价格/汇率不足继续标注，未调用实际行情、OpenD 或外部模型。
- 在历史表单关闭前尚未确认的本批记录只保留于当前页面；每段补录需覆盖到原起点并核对。既有真实负债或复杂待确认业务仍需对应事实，不用未知数据凑平，也未增加历史文件自动转换。
