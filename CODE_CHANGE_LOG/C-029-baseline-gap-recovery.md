# C-029：历史收益基准缺失时保留读取与补录恢复

## 原因与实际修改

C-028 取消成交自动报价后，曾依赖成交价建立的旧收益基准可能缺少独立报价。重放仍在基准估值不完整时抛 ValueError，账户、首页、持仓和复盘共用该读取路径，因而一起失败。此前检查覆盖普通缺价和新基准保存，未覆盖旧基准变得不完整后的多页面读取。

- 重放保留基准日期、记录 ID 和完整/缺失/净资产非正状态。旧基准无法核算时保留待补齐，不阻断账本、账户或持仓；该统计期金额、净值与比例保持未知，后续现金和已知当前资产仍可计算，不借用后来估值或原起点冒充所选基准。账户累计收益按独立契约计算。
- 保存新建/修改的基准时，仅针对该记录严格校验完整估值与正净资产；旧待补基准不阻断普通补录/纠错。数量、现金、转移等账本硬校验继续执行，成交价不参与估值。
- 在存在基准的同一观察时点，独立估值按原记录顺序预合并后计算基准，支持比原基准 ID 更大的后补记录，实际报价时间和较新记录优先规则保留。纠错/作废后重算，不把以后日期的价格倒填。
- 缺失项增加收益基准环节和交易日期，前端展示具体账户/标的/报价或汇率及原基准日期，避免跨日观察时间混淆。复用已有历史市值补录表单；已经清仓的标的仍按原时点定位。没有新增报价表或悬停明细。

## 验证与限制

- 30 项定向服务检查通过：新基准恢复文件中的 7 个服务场景，以及既有基准、报价沿用/交易分离、读取重放和选定累计结转检查。覆盖旧基准缺价、当前仍可估值、后续入金不换起点、基准 FX 缺失、净资产非正、已清仓标的补录、同刻后补顺序、纠错/作废及新基准仍拒绝不完整保存。
- 2 个内存 API 场景通过：分别在当前有报价/仍缺报价时，账户、持仓、首页及交易复盘 GET 均返回 200，组合曲线可读；POST 补录独立报价后原基准恢复且收益可算。使用隔离 SQLite、依赖覆盖及本地汇率桩，执行环境避开已知受限沙盒 TestClient 线程阻塞；没有启动应用服务或访问真实账目。
- 前端 TypeScript/Vite 构建通过，保留既有大包提示。实际组件离线浏览器 8 项检查通过：资产/持仓展示、统计期待补齐、基准日期与标的提示、原起点保留、定位历史补录、正确时点请求、保存后恢复和无脚本错误；截图已目视检查。临时脚本、虚构样本及截图在忽略的 `.runtime/c029/`，未提交。
- 真实 SQLite 以 `mode=ro` 及 `PRAGMA query_only=ON` 打开：组合重放、账户投影和持仓投影已返回，旧基准保持待补齐，Session 无新增/脏来源记录。当前仍有缺少独立报价的持仓，因此完整总资产可能未知；本批修复读取可用性，不伪造缺失市值或代填历史报价。
- 未启动/重启前后端，未写入真实账目、外部行情或模型；未运行全套测试。原始事实、已有基准标记和日期不迁移，实际运行页面及真实补录仍待用户验收。
