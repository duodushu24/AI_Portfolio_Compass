# C-020：按明确授权清空单账户并保留重新建账入口

关联 [P-005](../issues/P-005-portfolio-return-history.md)。用户明确要求指定账户全部清空并自行重录，替代上一轮保留旧成交的选择；本批只处理真实数据，不修改应用代码或新增重置接口。

## 实际操作

- 核对账户登记、按账户关联数据、专属代码及币种的使用范围；未发现需要同时核对对端的跨账户转账。先在已忽略本地目录保存 SQLite 一致性恢复副本及私有操作基线，在隔离副本试清空后再操作正式数据库。
- 在单事务内删除目标期初、成交、持仓来源、复盘及其专属估值，并清除包含旧目标资产的派生诊断。账户登记、名称和数据入口保留，汇总余额归零，不替用户创建新期初或虚构买入。
- 原共享估值中目标专属代码及其独占汇率事实一并移除；仍有其他账户报价的观察保留，并重新计算整体组合。已无剩余报价或汇率的目标专属观察删除；其他账户的原报价与记账事实保留。
- 恢复副本、脚本、删除清单和核对结果均留在已忽略运行目录，不写入公开文档或版本库。原个人文字、画像、通用设置及其他账户业务数据不在清除范围。

## 验证与限制

- 隔离试操作及正式操作均通过账本重放校验；其他已建档账户的完整账本、当前财务结果及清仓查询逐项一致，共享观察中其余报价内容不变。目标账户记录均已消除，未建档且无持仓、成交、清仓记录。
- 正式 HTTP 只读核对：期初 confirmed=false，来源期初无持仓且现金为零；记录/期初/持仓列表为空，清仓次数为零，账户列为未建档，重新设置期初入口可用。无需重启服务。
- 本批无应用代码变更，未运行无关单元测试、前端构建或新增浏览器验收。用户自行录入期初和真实买卖的功能验收尚未进行。
