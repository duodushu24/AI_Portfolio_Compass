## 1. 目标、范围与使用流程

统一 A 股、港股、美股、场内/场外基金所在的投资账户，实现持仓记录、买卖记账、现金与资金流、成本盈亏、账户收益统计及历史回顾。保留本地 React/Vite、FastAPI、SQLite；金融应用是体验参照，本项目明确自己的计算起点与口径。

首次设置账户起点，默认从首笔交易前的现金开始；也可选择已有持仓作为起点。日常入口为**记录买卖、记录资金、记录分红、更新市值**；分红复用独立资金事件，不增加买卖方向。系统自动更新持仓、现金、成本、收益与历史；用户不重复录成交、改持仓和另存收益。不强制固定周几或每日记录；任意时点、同日多次和补录都按实际时间保存。

| 操作 | 用户填写/确认 | 自动结果 |
|---|---|---|
| 首次设置起点 | 首笔交易前的日期及各币种现金；零现金可后续录首笔入金。已有持仓模式才填写数量、成本和当时报价 | 首次买入建立持仓和成本，报价单独录入；不重复录同一笔期初持仓 |
| 记录买卖 | 账户、标的、买入/卖出、数量、成交价、费用、实际时间；新增标的补充基本信息 | 更新数量、摊薄成本、现金，归零结算阶段清仓收益，保存历史与交易标记 |
| 记录资金 | 入金/出金、账户间转账、金额、币种、实际时间；分红/利息等在同一资金入口选择类型 | 更新现金与收益属性，避免新增投资被计作盈利 |
| 记录分红 | 标的、阶段、记账时间、净分红金额，币种随标的 | 视同到账，增加现金并扣减阶段净成本；旧资金入口兼容保留 |
| 更新市值 | 批量或单标的市价/净值或总市值、实际价格日期；必要的观察汇率 | 更新各页面采用的市值，自动形成收益观察点 |

市价/净值与标的市值任选一种输入，数量已知时换算另一项，只保存一套一致的报价依据。股票按数量单位，基金按份额与单位净值处理。清仓为“卖出全部”快捷操作；一般买卖无需另选加仓、减仓、清仓三种记录。

主编辑入口为“账户与数据”，保留账户管理及买卖、资金、市值与历史补录。原“持仓”更名“资产组合”，展示整体收益、配置和当前持仓；点击标的进入统一详情。组合页账户筛选只影响持仓表，不改变整体曲线，顶部不再提供单账户切换。

数据页排列为“数据管理 → 账户记账”，移除单账户收益指标和曲线。数据管理页签为持仓数据、已清仓查询、成交数据、行情数据、新闻数据。持仓只显示当前非零持仓，无“包含已清仓”按钮；点击标的查询成交事实，不再附账户收益曲线。保存/导入后账户账目刷新，返回组合页重读统一计算结果。

持仓表数量只显示数字，成本价与市值价分别显示单位价格，成本计算仍为摊薄法；持仓盈亏、持仓收益率、本阶段分红分别列出，币种独立，持仓市值默认 CNY。持仓盈亏已包含部分卖出和分红，不能再加一次分红；清仓收益单独查询。金额两位、单位价格保留必要小数，数字右对齐不换行。全组合按代码、币种和单位合并持仓，账户分布可展开。资产组合当前持仓在市值价之后列示“市值更新日期”，按原价格实际时间显示日日期，不增加独立报价表或节点悬停报价明细（C-027）。

已清仓查询每行对应账户、标的一次完整持有阶段，包含清仓后再次买回的过去阶段；提供清仓日期、关键词和账户筛选，默认清仓时间倒序，查询可独立选全部账户。摘要为清仓盈亏（CNY）、胜率、次数、涉及标的数，点击查看阶段成交、费用和结转成本。胜率按原币已知盈亏，持平计入分母、未知不计；人民币合计仅在各阶段历史成本和卖出时汇率完整时提供，否则显示已知部分与缺失次数。已有持仓/转入起点不能假定为真实建仓日；真实首笔买入阶段按北京时间自然日计算天数。不增加指数比较或平均持有天数。

验收补充（2026-10-18）：历史节点持仓表只展示该时点非零持仓；完整账本中的已清仓阶段和本次清仓成交仍保留。单币种清仓查询的主摘要按该币种显示完整已知原币盈亏，标签明确币种；混合币种保留人民币汇总及原币明细，成本未知不得将已知部分冒充完整金额。人民币资料缺失时不改写历史成本、不使用当前汇率凑数。

## 2. 持仓成本与买卖记账

### 2.1 唯一摊薄成本

数量与成本按**账户＋标的＋币种/数量单位＋持有阶段**定位，跨账户同代码先分别计算，再按展示口径汇总。已有持仓的期初摊薄成本确认一次，首次买入自动建立新标的成本；后续由已确认买卖和分红维护。兼容字段 average_cost 指摊薄成本，不代表第二套算法。

设剩余数量 Q，本阶段买入清算支出 B、卖出净收入 S、净现金分红 D。成交金额优先采用明确清算依据，费用只计一次：

```text
净成本 N = B - S - D
买入：增加数量与 B，减少现金
卖出：减少数量，净收入计入 S，增加现金或已确认待到账款
分红：净分红计入 D，现金同步增加；数量和报价不变
Q > 0：摊薄成本价 = N/Q；持仓盈亏 = 当前市值 - N
持仓收益率 = 持仓盈亏 / N（仅 N 已知且大于 0）
Q = 0：阶段清仓盈亏 = -N = S - B + D；买卖盈亏 = 清仓盈亏 - D
清仓收益率 = 阶段清仓盈亏 / 本阶段累计买入支出（分母已知且大于 0）
```

部分卖出和分红均会改变剩余摊薄成本，未清仓不单列清仓利润。归零后结算并保留原阶段，再买入重新计算，不继承旧收益或分红，包括同日回补。历史阶段补录分红只修正原阶段，不抵扣后来新阶段成本；不新增人工维护的收益表。

负/零净成本合法，非正或未知成本不输出比例。未知期初成本不因买卖或分红变成已知；旧持仓人民币取得成本无依据时仍未知。转托管按比例携带净成本，不虚构清仓或额外现金，既有持仓/转入起点也不能伪造真实建仓日期。

所有买卖包括首次买入都不生成或覆盖市值报价及日期（C-028）。首次摊薄成本为 `(成交金额＋买入费用) ÷ 数量`，与市值价独立；已有报价按交易后数量估值，无有效报价时提示缺价，通过更新市值补录。已持有起点继续使用当时报价，不以成本或成交价伪造历史市值。费用只计一次，账户级独立费用单独记账。完整分红归属、历史阶段及纠错行为见 P-007/S-001。

### 2.2 成交与调整

普通买卖记录已确认成交；分笔成交逐笔记录。卖出超过可用持仓需要核对，不能自动生成负持仓。期初数量/成本直接编辑只用于建档或纠错，不能凭两个快照的数量差自动推断卖出利润。

场外基金记录确认份额、成交净值及费用，保留实际成交/确认信息。未确认申购或尚未到账赎回保留待确认/待到账资产，确认与到账只是资产形态转换，避免某个观察点资金凭空消失。分红再投资按分红收入与买入联动处理，收入和成本各记一次。

拆分、转托管等如实际发生，应使用明确的调整事实保留成本连续性，不冒充普通买卖；融资、负债或未支持的数量单位需明确口径，不能静默按普通股票现金账户计算。

## 3. 现金、资金流与全账户范围

现金按账户和币种保存，买卖现金影响由成交推导，资金记录只保存独立事项，避免双重记账。至少覆盖外部入金/出金、内部转账、分红、利息、独立费用及实际换汇；转账/换汇包含两端信息并作为一次业务操作保存。

| 事项 | 账户资产/现金变化 | 对净值份额的处理 |
|---|---|---|
| 外部入金/出金 | 增减账户现金或明确的转入/转出资产 | 按发生时净值增减份额 |
| 组合内买卖 | 持仓与现金互相转换，费用减少资产 | 不增减组合份额 |
| 纳入范围内账户之间转账 | 转出端减少、转入端增加，费用单列 | 全账户汇总不增减份额 |
| 分红/利息 | 增加现金；分红视同到账并扣减阶段净成本，不另建应收分红 | 不按入金增加份额 |
| 换汇 | 两币种余额按实际兑换金额转换，费用单列 | 不按新增投资处理 |

资金流属性由所查看范围判定：全账户内部转账在单账户视图中分别是出金/入金，在全账户视图中是内部转移。一笔转账不由用户分别录两笔无关联收支。

全账户组合有明确的纳入范围和起点，账户的同步启用/停用不自动改变业绩范围。新增或移出账户记录生效日期、当时资产与质量，作为范围转入/转出处理，不直接拼接新旧资产规模制造收益。后端保留单账户和全账户的净值/份额状态用于账目校验，前端只展示整体账户级收益曲线，单账户百分比不直接平均为组合收益率。

清仓后现金仍在账户，总资产和收益曲线继续有效。全部出金导致资产/份额归零时保留已结束区间与最后有效收益，避免除零或显示亏损 100%；此后重新入金建立新的连续区间并明确起点。

## 4. 收益金额、净值曲线与手工市值

### 4.1 两类收益口径

**成本盈亏**用于解释持仓与阶段清仓：摊薄成本、含部分卖出及分红的持仓盈亏、持仓收益率和已清仓阶段收益，包含期初成本所反映的既有浮盈/浮亏；不能与基准后的组合收益直接相加。建档前已卖出利润缺失时注明覆盖范围。

**账户收益**以实际统计起点的总资产为基准，纳入现金、资金进出、费用、分红、汇率和明确的待确认资产/负债。页面展示累计账户盈亏和实际起点，不固定为软件建立日期：

```text
账户总资产 = 持仓市值 + 现金 + 待确认/待到账资产 − 负债
统计区间盈亏金额 = 当前总资产 − 期初总资产 − 期间净外部入金
```

两类指标分别标注，不能将已包含在期初市值中的浮盈再加到账户收益。逐段补齐更早真实交易后重建起点和区间，原期初不再重复初始化持仓。资金调整、更正或范围变化需按其真实属性处理，不作为收益兜底项。

### 4.2 净值/份额计算

主图默认**累计账户收益率**，可切换**累计账户盈亏金额**；持仓收益率放在持仓与标的详情中。采用净值/份额方法，完整出金后的连续区间规则保持不变：

```text
首次有效建档净值 = 1
期初份额 = 期初总资产（须大于 0）
入金增加份额 = 入金折算金额 ÷ 入金前净值
出金减少份额 = 出金折算金额 ÷ 出金前净值
当前净值 = 当前总资产 ÷ 当前份额
累计账户收益率 = 当前净值 ÷ 本连续区间期初净值 − 1
```

入出金增减份额，新增资本参与后续收益计算；保持不变的是收益率起点净值，不是一直用最初本金作分母。同一时点多个事项需有确定顺序，先计算资金流发生前资产/净值，再处理资金流，不能先把入金加入资产再倒算原净值。无有效资产/份额时不输出虚假百分比。

**虚构核对例子（已向用户解释）：**

| 时点 | 总资产 | 累计账户收益率 | 自建档盈亏金额 |
|---|---:|---:|---:|
| 开始投入 | 1,000 | 0% | 0 |
| 第一段上涨 20% | 1,200 | 20% | 200 |
| 再入金 1,000 | 2,200 | 20% | 200 |
| 此后再上涨 20% | 2,640 | 44% | 640 |

后一段收益为 2,200×20%=440，累计金额为 200+440=640；累计收益率为 1.2×1.2−1=44%。新增 1,000 元在净值 1.2 时取得 833.333… 份，份额总数增加至 1,833.333…；因此不存在固定本金分母。**累计收益率不能乘当前总资产直接换算累计盈亏金额**，不同批次资金投入时点不同。

资金流调整和发生时估值的设计参考 [GIPS 官方时间加权收益说明](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/)，用于解释本方案的收益计算原则。

### 4.3 手工价格与汇率

本轮补充（2026-10-18）：允许用一条明确收盘估值作为整体组合的新收益基准；账本仍从原期初完整重放，仅清除基准前的收益派生点和份额累计，基准当日归零，不改变买入成本或现金。基准必须覆盖已纳入账户的完整持仓、汇率和正净资产；基准之后没有估值的买卖日期不生成每日曲线，下一次完整观察按真实交易后的持仓计算。资金进出边界缺少估值仍阻止完整收益率，不因设置新基准而放宽。

周度曲线的估值线与交易记录均需展示：真实买卖在独立交易行标记，同日多笔按北京时间日期分组，可展开逐笔进入原时点详情；没有完整估值的交易不能放到虚构收益值上，也不能因为估值不完整而隐藏成交。交易详情显示标的、方向、数量、成交价、费用和数量/成本变化；已清仓标的不作为当时持仓行重复展示。

同一交易日各市场的收盘价可以组成一次估值，观察生效时间不得早于任一实际报价；报价保存实际时点，界面另标交易日期，避免跨时区误显示基准日。C-027 按用户确认允许当前及历史节点采用实际时间不晚于节点的最近有效价格，不再要求同刻或同批。用户明确标记的估算报价/汇率保存类型及来源；普通沿用不视为估算，不补造最新收盘价，不取未来报价填补历史。

手工更新市价/单位净值或标的市值是正式可用路径，保存即自动生成观察点；无需稳定实时源、每日价格或 K 线。图只连接实际观察点，横轴为真实时间，同日多次可以查看各记录；不生成不存在的日收益。

每个点保存持仓/现金依据、采用报价、实际报价时间、来源/价格类型、观察时间、汇率、总资产、净值份额、收益金额与质量。沿用旧价不改成今天报价；基金正式净值与估算分别标注。只更新部分标的时其余采用最近有效价格并标注时点，完全缺失部分不按 0 估值，也不显示完整准确组合收益。

没有资金流的区间可用两次资产观察计算收益。资金发生时采用当时最近有效报价/汇率；普通沿用不报警，用户明确标记的估算保留说明。只有真正无价/汇率时才提示具体账户、日期、标的及字段，并复用现有表单补录。金额依赖期初资产、当前资产及净入金；收益率另需资金边界估值，分别判断有效性，不因收益率缺边界就隐藏已可算金额。此口径基于已记录价格，不称为精确盘中或每日市场收益。

默认全账户以 CNY 汇总，保留原币金额。现金、市值和外部资金流按相应时点汇率折算，汇率记录固定保留，不能从覆盖旧值的当前汇率缓存回取。原币期初摊薄成本确认一次；历史人民币成本有依据则保存并续算，无依据时不拿建档日汇率伪造取得成本。**自建档净值收益以期初市值与当时汇率为基准，可与未知历史人民币成本明细分开计算**，不要求每次更新市值都重填成本。

历史汇率规则补充（2026-10-18，C-021）：买卖、分红、资产及资金折算共用已保存的汇率事实。本笔明确填写的有效汇率优先；否则选同币种、实际时间不晚于该事件的最近一条，不要求与成交精确到秒一致。后来录入但实际时间更早的历史汇率可重算原事件；不得以实际日期更晚的汇率倒填过去。实际时点相同有多条记录时按原记录生效时间及既有确定顺序决胜；编辑与作废后重新选择。当前同步缓存不作为历史成本来源，不自动补造汇率。

新交易允许依据上述历史汇率计算人民币成本，保留汇率、实际时间、来源、沿用/估算和本笔填写/历史取用依据；已经带入的旧持仓若原始人民币取得成本未知，仍保持未知，不能用建档时汇率换算成虚假取得成本。清仓时逐笔折算净买入支出、净卖出收入及分红，包含汇兑影响；原币盈亏不变。沿用或估算汇率形成的人民币结果明确标记，只有真正没有可用历史事实或取得成本未知时才提示缺失。

## 5. 数据职责与代码设计

### 5.1 事实来源和自动结果

| 数据 | 唯一职责 | 现有结构处理方向 |
|---|---|---|
| 已确认期初资料 | 每个账户的生效日期、期初持仓成本/数量与各币种现金、起点市值 | 从既有账户/持仓资料确认，建立明确关联；旧观察留作来源 |
| 成交 | 真实买卖、数量、价格、标准费用、币种与实际时间 | 复用 Deal，补必要规范字段；既有交易复盘保持原含义 |
| 独立资金/必要调整 | 入出金、转账、分红、利息、费用、换汇与明确调整事实 | 轻量独立记录，与成交共同进入同一计算服务 |
| 报价/汇率 | 一个标的币种/单位在某时点的价格或市值依据 | 统一手工、导入与未来适配器写入路径，复用/调整现有报价结构 |
| 持仓/收益快照 | 自动产生的数量、成本、现金、市值、盈亏、净值及质量 | 复用有价值的快照存储，作为可重建结果，不再成为手工账目 |

实际表名和必要字段在实施 C 中依据源码细化，不为迁就旧字段保留多套计算引擎。所有账户/标的定位和范围使用普通 ID、实际时间、来源；不引入内容哈希、严格版本链或泛化事件平台。现金/成本/价格/份额新计算使用 Decimal，展示再舍入；计算精度、货币与数量单位统一。

### 5.2 后端与前端组织

后端集中在投资组合业务目录，初步按三项职责划分：

```text
backend/app/services/portfolio/
  ledger.py       # 摊薄成本、持仓阶段、现金，应用成交和资金/调整事项
  performance.py  # 报价/汇率估值、净值份额、盈亏与观察快照
  service.py      # 业务校验、事务、保存、更正、查询及重建
  gf_import.py    # 券商联合明细适配、来源核对和重建
```

路由为薄接口，优先沿用现有 REST 风格，提供期初确认、成交录入、资金录入、市值更新、历史/详情查询与记录更正/作废。文件可以按实际复杂度合并，避免为空职责预建抽象层、通用仓储或队列。

`main.py`、`sync.py`、`return_history.py` 中相关公式/查询集中迁入或改为调用同一服务；总览、账户页、持仓、标的详情及已有诊断都读取同一数据结果。前端不再计算金融口径，负责输入、展示与图表。保存一个业务操作在同一事务中完成，派生缓存和状态失败时不留下半套账目；补录/纠错用确定性的时间排序重建受影响结果，本地规模优先一次读取并按时间重放。

前端相关持仓表、买卖表单、资金表单、市值更新、收益图和标的详情集中在一个 portfolio 功能目录；页面复用组件与 API，不分别实现同一编辑器。不做无关日记、提示词、Agent 或全项目结构重写。

统一详情展示当前/已清仓状态、原币摊薄成本、持仓盈亏、阶段清仓收益、可用币种口径、买卖/资金关联及历史收益。K 线、AI 与新闻继续按各自已有能力展示，收益计算不依赖它们成功。清仓标的从历史列表或检索进入同一详情，不依赖当前持仓接口才能打开。调仓点点击显示真实成交、前后数量/成本/盈亏；缺少同时点完整报价时不宣称精确市场与调仓归因。

## 6. 纠错、导入与既有实现处理

保留既有资料、Git 历史与有价值的存储/图表/测试；本次设计不直接回退代码或迁移私人数据库。代码回退不能撤销已写入 SQLite 的数据。实施先核对受影响记录和数据转换，保证可恢复与来源可追溯，不用删除现有历史换取表面简化。

从现有标准持仓中选明确日期确认期初，价格/现金/币种需核对。期初之前资料可继续查看，不将零散观察自动视为完整成交；旧 Deal 在起点前不重复驱动新账目。期初之后的规范成交驱动成本/现金，持仓导入用于核对差异，不能同时覆盖自动账目又追加成交造成双计；源文件重复确认的防重只沿用必要导入规则，不扩展成版本追踪体系。不新增旧混乱 Excel/长文本兼容解析器或全量历史恢复前置。

来源核对按快照实际时间还原账目，而非比较旧导入数量与今日持仓。起点前来源返回未覆盖状态，不当作缺少成交；相同日期数量/成本不一致才报警。定位同时包含币种/单位，浮点来源允许有限舍入差。只有完整快照可以核对缺席标的的零数量，部分资料仅核对提供行；日期与两侧数量/成本对用户可见。

### 6.1 从首笔交易开始及向前补录

新账户默认无期初持仓，设置首笔交易前的真实现金，或零现金加首笔入金；之后逐笔记录首次/后续买卖。已确认起点不因录入更早日期而静默移动，避免同一持仓被初始化和买入两遍。

已有账户提供“补录更早历史”：选择早于原起点的新日期、当时现金和汇率，在复用的买卖/资金表单中添加新起点至原起点之间的记录。添加到本批仅留当前表单；试算通过原服务与确定时序重放，回滚所有写入，不生成已保存账目。核对原起点数量、已知成本、各币种现金、负债及待确认款项；差异明确列出，保存必须重新核对并获得界面上的差异确认，不能自动补造资金来凑平。

确认后原起点与新增记录在同一事务保存，非法数量/现金或关联失败全部回滚。原起点资料保存在同一账户的核对资料中，原报价/汇率成为当时观察事实，旧持仓不再初始化。明确设置过的组合纳入日期保留；原本随起点默认纳入的日期随新起点前移。继续使用统一摊薄成本、现金与净值引擎，无新增收益算法或数据库草稿系统。

用户可逐段填写规范历史，但只有交易不足以恢复所有账户收益；真实资金进出、费用、分红、汇率与必要报价也需补齐。曲线只连接有依据的时点，缺价/沿用与资金边界估算继续标注，不合成每日历史价格。

旧“记录收益”入口归并为“更新市值”的自动保存结果。当前与历史价格读取规则集中，修复账户/持仓表与收益图采用不同价格或公式的问题。原持仓观察/批次可用于迁移和来源核对，但不与新期初＋成交账目并行决定已建档账户的持仓。

普通记录 ID 用于修改/作废，允许更正实际时间、账户/标的、数量、价格和费用并重建后续；不继承旧方案锁定标的/时点或按 12 小时近似定位行的限制。日常新报价追加事实，历史报价更正只作用于明确记录与受影响派生结果；历史观察采用的价格不因今天抓到新价而被替换。误删/作废不生成虚构卖单，更正与真实买卖的含义清楚。

## 7. 开发顺序与有限验收

本次按完整业务闭环交付。内部开发可依次建立期初/账目计算 → 买卖与资金保存 → 市值与净值 → 页面统一/历史重算，但不是 S-001 后续阶段，也不将单独可录收益观察当作目标完成。自动行情适配器以后独立增强，不阻断本闭环。

| 验收场景 | 必须满足 |
|---|---|
| 首次建档与买卖 | 期初只确认一次；买卖更新摊薄成本，部分卖出不单列清仓收益；分红增加现金并扣减成本，手续费只计一次；清仓结算并重置，再买入历史保留 |
| 资金与净值 | 1,000→1,200→入金 1,000→再涨 20% 为 44%/640；入出金不产生虚假盈利，金额与收益率各按正确口径计算 |
| 范围与转账 | 全账户内部转账不改变收益，单账户正确识别流入/流出；账户纳入/移出不制造绩效；清仓保留现金，全部出金不除零 |
| 市值更新 | 一次更新自动保存时点和曲线点，账户/总览/持仓/详情一致；单标的与跨账户合并均正确，同日与不规则时点可查 |
| 缺失与特殊事项 | 原币/CNY和现金汇兑不混用；缺价/旧价/缺汇率、资金流估算、基金待确认、分红利息及费用处理透明，不按零补齐 |
| 补录、纠错与导入 | 更正早期成交/资金/价格后重建后续数量、成本、现金、净值；重复确认不双计，导入差异不覆盖账目，原资料保留 |
| 用户操作 | 建档→买入→部分卖出→资金进出/转账→更新市值→清仓→查看详情与曲线，一条流程完成；没有重复维护持仓/收益的步骤 |

验证使用隔离 SQLite 与虚构金额，直接测试公共计算服务和关键接口；按风险选择前端构建及必要浏览器流程，不运行无关全套测试，不调用真实模型或收费行情。技术验证与用户真实账目验收分开，新方案不能引用旧 C-007 的通过结果宣称已完成。

完成条件不包括稳定实时行情、K 线修复、从旧混乱资料自动恢复全部历史利润、交易执行或 Agent 检索。支持规范历史逐段录入与重建，不推断用户未提供的事实。基础实施见 C-008，试用后的页面收敛与历史录入见 C-010；技术验证与用户真实账户验收仍由 P-005 分别跟踪。

## 8. 已确认的券商联合导入范围

用户授权对账单与资金流水联合重建指定账户，其他账户及个人文字记录保留。先按来源标识合并、逐笔核对现金和证券余额，再以隔离数据库试写；保存恢复副本后单事务替换期初、作废旧成交和旧资金，保留已有明确报价与来源观察。重复批次不得双计，来源冲突或已有跨账户转移必须停止。

费用合计与分项不重复相加，实际成交/清算金额优先于舍入均价乘数量。份额入账只增加目标账户数量并保留总成本，不影响其他账户。原始业务时间和账务行顺序分别保存；时间排列不同的来源以日终余额核对正式时间回放。

历史决策：C-013/C-014 曾对导入账户采用仅明确报价模式，限制其他日期价格和估算用于历史点。该同刻限制已由用户在 2026-10-20 授权的 [C-027](../../../CODE_CHANGE_LOG/C-027-valuation-carry-data-prompts.md) 替代：允许沿用当时最近有效报价及显式估算，保留原日期/类型；仍不把该导入账户的成交价当成市场报价，不以未来价格补历史。单位变更后不可继续使用失效报价，金额与收益率独立判断。原始导入、基准及周度观察均保留，不再要求重新导入账目。
