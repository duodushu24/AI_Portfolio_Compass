# P-010 / S-001：账户起点与历史结转

所属问题：[P-010](../../P-010-account-onboarding-profit-carry.md)。首次确认并实施：2026-10-18；2026-10-19 按用户反馈调整空白结转及收益展示（C-024）、累计/统计期视图与日曲线（C-025），并增加缩放和平移、缺失区间说明（C-026）。

2026-10-20 用户确认最近有效报价规则、具体资料补录提示与简化日期列，由 [C-027](../../../CODE_CHANGE_LOG/C-027-valuation-carry-data-prompts.md) 实施，替代旧导入账户历史节点必须同刻报价的限制。

## 用户流程

复用账户与数据页面，标准起点模板包含账户起点、资金余额、当前持仓三页，一份文件绑定页面所选账户。时间不带时区时按北京时间解释。现金必须明确填写，零与未填写分开；持仓成本未知时允许留空，历史结转留空按 0 计入。报价与市值二选一，按实际数量换算。上传后打开与手工建立起点相同的表单，允许核对/修改；调用实际保存路径试算并回滚，修改后重新试算才可确认。

保存仅建立 PortfolioOpening，不把期初持仓伪造为买入、把结转伪造为现金或清仓。有效初始文件再次确认不重复建账；资料已纠错时拒绝旧文件覆盖。已建档账户的持仓导入只作为来源核对，买卖仍进入统一成交账本。旧模板平均成本不自动确认为摊薄成本；用户须在建立起点时核对。

## 收益契约

PortfolioOpening.data 保存 historical_profit_cny（金额字符串）和 historical_profit_note。新保存时空白转为 "0"；读取旧记录时，字段缺失、null 或空字符串同样按 0 计算，不迁移或改写运行数据。纠错未提交此字段时保留原值，明确清空时归零。结转不参与 Ledger 的现金、成本、清仓或净值份额。

对每个账户保留独立期初资产、期初人民币持仓盈亏、历史结转以及自起点净外部资金。累计盈亏＝历史结转＋期初持仓盈亏＋当前净资产－期初净资产－自起点净入金。内部现金/转托管两端匹配；汇率缺失、期初估值或人民币成本缺失时相关结果未知，不补造。基准重置及连续区间重开仅影响统计期净值，不重置账户累计盈亏。

组合按当时纳入账户汇总；任何账户因成本或估值等资料缺失无法核算时，完整累计为 null，另提供完整核算账户合计和缺失账户。选择累计视图时，无法核算则显示“待补齐”及缺失账户，不自动替换统计期金额；收益口径详情披露账户拆分。未知/非正成本不制造持仓收益率；导入前的清仓与分红明细不伪造。

累计净投入＝同一时点净资产－累计盈亏；累计收益率＝累计盈亏÷累计净投入。后端 profit.py 对当前摘要和各历史点统一派生，组合按汇总金额计算，不平均各账户收益率，不用今天资产作历史分母。净投入为零或负数时收益率为 null，金额仍可用；与统计期净值收益率分别命名，说明提取本金会改变该比例。

## 收益视图与日曲线

右上角提供累计收益率、累计盈亏、统计期收益率、统计期盈亏四项，默认累计收益率；摘要金额、摘要收益率和曲线口径同步。资产及现金不随视图变化。累计曲线使用已有观察点及当时结转，不补画建档前走势；统计期仍遵循既有基准和连续区间，缺失处断开。

每个日期显示最后一次有净资产估值的观察；该观察的累计收益率若因净投入不适用，保持缺失，不回退当天较早收益率。保留全部同日记录，点选可展开；同日真实交易仍独立合并标记，不制造无估值日的收益点。日期优先 valuation_date，否则取北京时间对应日；曲线、提示和节点标题只显示日期，不带时分秒或“收盘”。首节点与跨年首节点用 YYYY-MM-DD，其余用 MM-DD。

纵轴使用整齐刻度，始终包含加深的零线和明确 0 / 0% 标签。默认在窗口内显示全区间，不再为日期标签扩展超长画布。日期标签用 11px、上下错行并按空间自动疏密；所有原观察点保留，悬停或键盘聚焦可看完整日期。支持滚轮及按钮缩放、放大后拖动平移、底部范围两端手柄，以及“全部”恢复；切换收益指标保留查看范围，缩放不改变上方收益统计。

灰点仅标记当前指标无法计算，不表示零收益。前后已知值之间若有缺失记录，使用独立虚线并注明中间日期无收益数值，不填补缺失点；统计期跨基准/连续区间仍不连接。累计口径可以跨净值区间编号连接已知观察，金额和比率仍来自后端。PortfolioChart.tsx 负责渲染及交互，chartLayout.ts 负责日期、日分组、指标、刻度、范围边界及线段规则。

## 边界与维护

### 报价沿用与缺失补录

每个观察点使用实际报价时间不晚于该点、代码/币种/单位一致的最近有效单位价格，乘当时数量。部分标的更新不使其他已有报价失效，不保留过期的总市值。当前与历史采用同一规则；无既有报价时保持缺失，不能用未来报价、成本价或零值凑数。拆分调整保留估算标记，红股入账后需有适用的新单位价格。用户在 2026-10-20 明确所有买卖不更新市值价，[C-028](../../../CODE_CHANGE_LOG/C-028-trades-do-not-update-market-prices.md) 因而统一取消手工/导入账户的成交自动报价，包括首次买入；不再保留成交参考价分支。报价来自起点确认或独立估值，交易只改数量、成本和现金，清仓后无价持仓不再阻止已可算净值恢复。

统计期盈亏金额只依赖期初资产、当前资产和净外部资金；净值收益率额外依赖每次外部资金进出时的完整估值。分别判断有效性：缺边界报价而资金金额明确时，允许显示盈亏金额，收益率保持未知。汇率或外部资金金额本身未知时也不输出虚假净入金合计。重算只修改派生值，不改写原账目。

旧收益基准在新规则或历史纠错后缺价、缺汇率或净资产非正时，读取保留原基准日期并返回待补齐状态，不阻断账户/持仓/首页/复盘，也不静默换为后来完整估值作为起点。该统计期的金额及净值比例保持未知，累计收益仍按其独立依据计算。新建或修改基准时仍校验完整性与正净资产；普通补录或纠错可在旧基准待补齐时保存。同一基准观察时点的独立报价先按原记录顺序合并，再核算基准，以支持后补记录 ID 大于原基准；不引入成交价或未来日期价格。已清仓标的仍可从具体缺失项定位历史持仓补录，保存后按原基准重算（C-029）。

后端分别提供当前估值、统计期及累计收益的结构化缺失项，包括账户、日期、标的/币种、缺失字段、发生环节与补录入口；开端成本、价格、汇率及历史人民币剩余成本分别指出。前端按当前口径合并同一项提示，打开现有账户起点或市值表单，预填账户与缺失时间，历史标的已清仓/转出仍可补单位价格。起点纠错保持先试算后保存；普通估值保存后刷新收益。

正常沿用已保存价格或汇率不视为错误/估算，不逐条黄色报警。用户明确标记的估算仍可计算且保留类型、来源和说明；有价就计算实际观察点，真正无依据时才显示缺失点和原有虚线。资产组合当前持仓在“市值价”之后增加“市值更新日期”，按北京时间显示 YYYY-MM-DD，采用原价格时间而非上传时间；跨账户日期不同的合并行显示最早日期，展开看各账户。表头“摊薄成本价”改为“成本价”，摊薄公式不变。不新增报价记录表、节点悬停报价明细或日常更新催促。

profit.py 负责纯派生结转统计；performance.py 在现有重放中调用，不新增逐账户重复重放。opening_import.py 负责标准模板解析与初始文件确认；service.py 持有保存、试算回滚和校验。前端 OpeningEditor 为手工与 Excel 共用入口。普通读取和试算不触发写后刷新，真实保存继续失效缓存。

未建档账户的旧持仓和成交表恢复单条删除入口，沿用已有接口及确认流程；不恢复旧新增/编辑路径。已建档的派生持仓仍通过起点纠错或原账目作废维护，删除来源记录不伪造卖出、现金或清仓收益。

向前补录历史时重新填写新起点之前的结转，比较原起点人民币成本与累计盈亏；原起点结转保留在检查点，不能自动把旧结转叠加到已补录的收益上。估值纠错保留收益基准/交易日期、汇率估算及来源，成交纠错保留明确成交金额。

本设计不接通所有券商格式、不新增自动行情、不会自动替换正式账目。人工/API 的既有行情入口保留，低频收盘源增强另行确定提供方与口径。
