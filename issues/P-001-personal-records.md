## 问题与目标

现有成交复盘依附交易，不能承载独立投资日记。目标是建立“自由记录原文 → 分析与讨论 / 录入外部总结 → 明确确认 → 保存可查阅总结”的完整记录流程，为日后 Agent 调用保留规范资料。

2026-10-04 用户限定本次范围为日记写入、提炼和保存，Agent 分析等记录部分完成后再做；原文直接保存，AI 结果可继续讨论，直到用户确认后保存。不兼容旧 Excel、混乱旧长日记，不使用哈希或复杂版本索引；旧资料和 H2 以后逐步规范录入。

2026-10-07 补充：AI 以投资教师角色分析观点、解释机制与偏差，支持多轮讨论、外部总结录入和可维护标签库；完整讨论要保存，意外关闭后可恢复、复盘可回看，但讨论与候选不因此成为已确认总结。

## 关键决策与理由

- **数据库作为规范入口，Markdown 作为阅读副本**：便于未来按主题调用，替代早期“知识库唯一权威、数据库仅索引”的设想；本期不支持外部 Markdown 自动回灌。
- **原文直接保存，正式总结明确确认**：减少录入阻力，保留用户原话及对 AI 结论的控制；讨论保存只为恢复与回看，不进入 Agent 默认正式检索。
- **轻量关联与可纠错内容**：普通 ID、年月日文件和自由主题足够，不为旧格式兼容、哈希或版本链增加复杂度；旧资料/H2 以后走统一流程。
- **完整聊天保留与候选状态独立**：替代仅页面内存的初版聊天方案，避免意外关闭丢失；新增讨论后需重新整理总结，确认前不替换已确认内容。
- **分析深入、总结收敛**：分析负责教学解释，总结保留结论、必要依据及边界；格式与提示词优化不增加模型调用次数或改动存储结构。
- **范围收敛**：不做持仓/成交原始索引、历史自动导入、自动画像/规则更新或 Agent 检索；旧路线图不作为实施入口，也不反向扩大本问题。
