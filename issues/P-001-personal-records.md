## 方案尝试

### S-01｜日记写入、对话提炼与确认保存｜2026-10-04

#### 分析依据

- **现状**：现有 `TradeReview` 依附成交，不能直接承载独立投资日记。知识库目录重整和 H2 选择性迁移已经完成，但日记输入、提炼对话与确认保存尚未开发。
- **本次范围**：建立“原文直接保存 → 按需 AI 提炼 → 对话调整 → 用户确认 → 保存提炼结果”的完整流程。日记不要求关联成交，允许记录思考、计划和未发生交易的经历。
- **存储方向调整**：规范数据库保存日记原文与已确认提炼结果，作为后续 Agent 的统一资料入口；Markdown 按年月日提供人工阅读副本。此前“知识库为唯一权威、数据库仅为可重建索引”的设计不再作为本次实现依据。
- **维护方式简化**：普通数据库 ID 只用于关联日记和提炼结果；内容允许直接纠错，不引入内容哈希、版本快照、修改时间校验、文件监听或外部编辑冲突检测。数据库与 Markdown 的一致性由应用保存动作维护，不靠日常校验历史版本。
- **阶段边界**：本次仅准备主题、关键词、日期、内容类型与关联关系，便于日后调用；不实现 Agent 的历史检索策略、工具选择、组合分析流程或画像与规则自动更新。旧资料以后按统一格式逐步录入，不为旧 Excel、长日记或 H2 编写专用兼容解析器。

#### 实施方案

**2026-10-04｜更新后的实施方案，待开发。** 以下路径、字段和交互是按本次要求细化的实现建议，不代表功能已经上线。此前方案中的临时文件、历史格式兼容、哈希版本校验和 Agent 工作流改造安排均由本方案替代。

#### 1. 写入与查阅

- 在现有复盘入口增加独立“投资日记”页面。日期默认今天，正文必填；标题、主题、关键词可选，允许先自由写下原文。
- 用户点击“保存原文”后直接创建或写入正式 Markdown 文件，并保存对应数据库记录；不创建临时 Markdown、草稿文件或待审核原文，不调用 AI 后才决定是否保存。
- 列表支持按日期浏览和简单关键词搜索；详情展示原文及对应的已确认提炼结果，提供编辑和“开始提炼”入口。这里只做记录管理查询，Agent 检索留到后续阶段。
- 保存后的原文允许在页面直接修改，同日允许多次记录。AI 不替用户改写原文；提炼对话中的解释或补充也不自动回写原文。

#### 2. Markdown 目录和文件约定

原文保存到知识库投资主题下现有的 `01_原始资料/复盘日记/`，采用“年 / 月 / 月.日.md”：

```text
01_原始资料/复盘日记/
└─ 2026/
   └─ 10月/
      ├─ 10.04.md
      └─ 10.05.md

02_分析与复盘/日记提炼/
└─ 2026/
   └─ 10月/
      ├─ 10.04.md
      └─ 10.05.md
```

- 首次记录某日时直接创建该日文件；同一天新增内容写入同一日文件的独立条目，数据库逐条保存，不覆盖已有记录。
- 每个条目只需简短标题或编号和正文；提炼文件另列关联原文、主题、关键词与确认后的内容，不展示长哈希或技术版本字段。
- 用户修改某条记录后，应用根据数据库的当前内容重新写入对应日文件。修改记录日期时同步调整原日期与新日期的日文件内容。
- 原文与提炼分别保存；提炼文件仅在确认后创建或更新。提炼结果按所归属的日记日期归档，跨日讨论不改变原文日期；阶段性历史分析以后规范录入时另填覆盖起止日期。
- Markdown 用于人工阅读；本期通过应用修改记录，不实现外部 Markdown 编辑自动回灌数据库。后续 Agent 读取规范数据库，不直接扫描这些目录。

#### 3. AI 提炼、讨论和确认保存

交互顺序：`原文已保存 → 开始提炼 → 查看候选结果 → 提问或要求调整 → 确认当前结果并保存`。

1. **开始提炼**：用户主动触发，输入当前选中原文和可选的关注问题。沿用现有模型配置及外部模型授权；未配置、未授权或调用失败时保留原文，明确提示未完成提炼。
2. **候选结果**：AI 给出简洁的事件梳理、值得保留的认识、解释依据与不确定之处，并建议主题和关键词。先理解原文，不预设偏误标签，不把没有写明的动作、情绪或结果补成事实。并非每条日记都需要产生行为判断。
3. **继续讨论**：提供与该条记录关联的对话区域，允许质疑、补充和要求重写。每轮调整后展示一份完整的当前候选结果，用户可以直接修改文字、主题和关键词。
4. **确认保存**：只有点击“确认并保存”才将当前候选结果及主题、关键词写入正式提炼数据和 Markdown。保存的是页面上正在确认的完整结果，不是较早一轮回答或零散聊天消息。
5. **后续再调整**：已经保存的提炼结果可以重新讨论；讨论期间仍保留现有已确认内容，直到用户再次确认后替换。不为每轮回复创建一份正式分析文档或版本记录。

未确认的内容仅留在当前页面会话中，不进入正式提炼表、Markdown 或后续检索资料。第一版不要求恢复未确认的跨会话讨论，离开页面时明确提示其尚未保存。用户提供的解释性补充可以体现在最终确认结果中，但不能伪装成日记原文里的同期表达。

原文纠错后，不用哈希或时间戳自动判断旧提炼是否失效；详情继续并列展示原文与已确认结果，用户需要时主动重新提炼。画像和投资体系的修改不属于“确认提炼”的含义。

#### 4. 规范数据库与保存职责

复用现有 SQLite，建议先建立两类业务记录；字段以可维护和便于主题匹配为目标，不建立复杂版本链：

| 数据 | 最小字段 | 用途 |
| --- | --- | --- |
| 日记原文 | 普通 ID、记录日期、可选标题、正文、可选主题/关键词、来源类型 | 保存用户写下的完整内容，供管理及后续原文调用 |
| 已确认提炼 | 普通 ID、关联日记 ID 列表、归属日期或覆盖期、标题、提炼正文、主题、关键词、来源类型 | 按主题查找已确认内容，并按普通 ID 回到原文 |

- 主题用于概括内容，关键词保留具体标的、事件或表达。提炼时由 AI 建议、用户确认；不要求写日记时先完成分类，也不使用大而固定的心理标签表。
- 提炼正文保持可读段落，说明事实、用户认识与 AI 解释的区别；事实依据尽量关联原文，允许保留“信息不足”。不为了结构完整强行生成大量空字段。
- 普通 ID 用于关联和更新；不作为内容版本号。修改日期如因日常管理需要保留，也不参与正确性校验、检索准入或强制重新分析。
- 后续 Agent 只能通过规范数据库取得原文及已确认提炼；未确认候选不作为可检索记录。本次不实现语义检索、向量数据库、检索工具或分析工作流，只确保上述字段和关系可直接复用。
- 用户新增、编辑、确认均通过同一个保存服务维护数据库与对应 Markdown。直接写正式文件，不引入临时文件替换流程；数据库写入和文件写入不能视为同一个原子操作，任一失败必须显示实际状态。
- 若数据库已保存但 Markdown 写入失败，提示“记录已入库，文件保存失败”，允许按该记录重新写入；重试更新原记录，不重复新增。数据库失败时不报告保存成功。这里只保留基本错误处理，不扩展为复杂版本同步系统。
- 日记、模型输入输出和运行数据库均为私有资料；演示数据不得写入真实知识库。公开代码、issue 和测试夹具不包含真实日记正文。

#### 5. 历史资料与本次开发边界

历史资料等新框架建立后再逐步整理：选择少量旧日记，人工调整为规范条目，走同一录入、提炼和保存流程进行测试。无需兼容旧表格列、旧 Markdown 标题或历史文件布局，也不要求重新分析全部历史记录。

H2 总结以后按同一套规范分析字段录入，保留“历史 AI 分析”来源说明、主题及覆盖期；已有内容可以直接整理为待确认结果，经用户确认后保存，不必为入库再次生成整篇分析。能够关联规范日记时补充普通 ID；尚未录入对应原文时注明关联缺失，不伪造关联，也不强制整批导入。该整理不作为本期功能交付前置条件。

本期不包含持仓与成交原始资料索引、历史文件自动导入、目录监听、复杂版本追踪、自动画像更新、投资规则更新，以及现有 Agent 工作流改造。后续分析流程在本 issue 的记录功能完成并验收后，再由 `issues/P-002-evidence-reflection.md` 推进；其旧方案不能反向扩大本次开发范围。

#### 6. 实施顺序与验收

| 阶段 | 实施内容 | 直接验收标准 |
| --- | --- | --- |
| 第一阶段：原文保存 | 日记数据结构、年月日文件写入、录入页、列表和编辑 | 保存后能打开 `2026/10月/10.04.md` 并在数据库查到正文；重启后可查阅；同日新增不覆盖，修改可正常保存；没有临时 Markdown 或哈希版本依赖 |
| 第二阶段：提炼对话 | 当前原文提炼、候选展示、连续讨论、手动修订与确认按钮 | 能质疑并调整结果；确认前没有正式提炼记录或文件；确认后数据库与 Markdown 保存页面上的最终内容；模型失败不影响已保存原文 |
| 第三阶段：整理与验证 | 已确认提炼的查看和修改、主题关键词字段、简单管理查询、保存失败提示 | 能按主题或关键词找到已确认结果并关联原文；重新讨论不提前覆盖旧结果；保存失败有明确提示，重试不产生重复记录；演示与私人资料隔离 |

验收采用与上述行为直接相关的最小测试和页面检查，不运行无关的全量测试。历史日记与 H2 的批量规范录入、后续 Agent 检索及投资分析另行安排，不以它们是否完成判断本次日记功能是否交付。
