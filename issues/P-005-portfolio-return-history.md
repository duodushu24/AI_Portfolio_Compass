## 问题与目标

资产分散于多个账户，覆盖 A 股、港股、美股及场内/场外基金。目标是在本地系统记录全账户持仓、买卖、资金和价格，自动计算持仓成本、现金、已实现与浮动盈亏、账户总资产及累计账户收益。

新账户默认从首笔交易前的现金开始，也可先设置零现金再录首笔入金；首次买入自动建立持仓、成本与报价。已有持仓仍可作为明确的统计起点，日常只记录买卖、资金变动和更新市值。已有账户需要追溯时使用“补录更早历史”，试算核对原起点后统一重建，避免旧期初与历史买入重复计入。主图统计已录入区间的全账户净值收益率和盈亏，起点由真实记录决定，不以软件建立日期为固定边界。

手工市价/净值或标的市值更新即可形成真实观察点，支持任意时点、同日多次和历史补录；记录实际报价时间。先完成手工闭环，稳定自动行情及 K 线不作前置。周复盘只是使用习惯，不固定记录间隔。

金融应用是功能体验参照，不保证不同平台的收益公式一致；本项目明确统一计算口径、起点、账户范围和准确/估算状态。

## 原问题与本轮解决

旧实现的问题来自用户试用和源码核对；本轮解决依据 C-008 及隔离验证：

- 原持仓观察与成交、现金分离，需要重复维护；现在确认期初后由买卖与资金事实统一驱动数量、平均成本、现金和利润，原观察保留为来源。
- 原价格观察不影响持仓表、账户资产；现在报价与汇率按实际时间共享，所有当前页面读取同一账目投影，市值保存自动生成收益点。
- 原详情依赖当前持仓，清仓后不能打开；现在清仓利润、买卖和按需收益曲线在同一标的详情中可查，橙色调仓点显示实际数量/成本变化。
- 原曲线仅为持仓收益；现在现金、外部资金流、组合内转账和汇率进入净值/份额计算，成本盈亏与自建档业绩分开。行情/K 线和真实账户验收仍是独立未验证事项。

### 试用反馈与关键修正（C-010）

- **重复展示与页面层级：** 数据页按“数据管理 → 账户收益 → 账户记账”排列；顶部统一持仓表提供“包含已清仓”和收益详情，中间不再重复列持仓。模块标题同级，旧“由上方账目维护”改为位置无关说明；一次买卖、资金或市值保存及导入刷新相关表格、曲线和账目。
- **清仓只有金额：** 清仓收益率按本持有阶段的已实现盈亏合计除以卖出结转成本合计，包含分批买卖和费用；再买入后保留历次清仓详情，累计利润与最近一次清仓收益率分别标明。未知或零成本不输出比例，转托管不虚构清仓。
- **旧快照误报：** 来源数量和成本改与快照实际日期的账目比较；早于统计起点标为“尚无法核对”，不说缺少卖出。仅完整快照可用缺席标的核对零持仓，部分导入不能推断其他标的不存在。来源保持只读，差异显示日期、数量和成本。
- **首次买入与期初价格：** 用户确认先录首次买入时间和价格。采用一笔真实买入自动生成数量、平均成本与初始报价，不重复录期初持仓。成交价作为首次报价，买入费用计入平均成本；零费用时二者相同，有费用时允许初始浮亏。已有持仓快照的平均成本不能直接伪装为当时报价。
- **历史起点向前移动：** 新起点在更早首笔交易之前，本批录入截至原起点的真实买卖、资金。试算不落库，核对原起点数量、已知成本、现金及待确认款项；差异需明确确认，非法账目回滚。原起点资料保留为核对依据，其报价保留为日期事实，后续重放不再重复初始化旧持仓。不补造入金、交易、历史价格或完整每日曲线。
- **名称问题结论：** 用户重启前后端后已解决，属于运行接口未加载此前更新；本轮不增加账户名称修正。

## 关键讨论结论

- **2026-10-17 展示范围已确认**：组合整体收益是默认且唯一账户级曲线；账户选择仅筛选持仓/查询，不改变该曲线。分账户记录、计算校验和资金边界继续保留。清仓查询按完整持有阶段，退出后再买入不丢历史；胜率按原币已知盈亏计算，历史汇率或人民币成本缺失时不生成完整人民币合计。

- **用户已确认**：只用平均成本；完整账户收益包含现金及资金进出；逐步从首次买入录入历史，不以软件建立后的收益为主要目标。成本由首次买入及后续买卖自动维护；已有持仓可确认一次期初成本；手工市值形成观察点，操作与代码简洁。
- **当前设计**：平均成本负责持仓与卖出盈亏，净值/份额负责累计账户收益率；账户收益始终标明实际统计起点。已有持仓起点可能包含之前的浮盈，向前补齐真实交易后重算完整已录入区间。累计收益率不能乘当前资产换算累计利润，新增资金通过份额参与后续计算。
- **统一业务入口与计算**：账户与数据负责编辑，持仓与标的详情负责展示；可添加复用表单的快捷入口，所有页面调用同一后端服务。期初、成交、独立资金事项及报价为事实，持仓和收益快照为派生结果。
- **完整交付闭环**：初始建档 → 买卖 → 资金 → 市值更新 → 持仓/现金/盈亏/曲线一致更新。内部开发可按依赖顺序推进，不以旧 S-001 阶段或独立收益录入作为产品分期。
- **事实与质量边界**：外币按币种保存，汇率保留实际时间；资金发生时缺少报价可估算并标注，补录后重算；未知状态不按零值。既有资料保留为来源，规范建档前缺失的历史利润不编造。
- **轻量维护**：保留 React/Vite、FastAPI、SQLite，普通 ID/时间/source 即可；不建立哈希版本链、泛化事件平台、复杂队列或新增 Agent 工作流。
