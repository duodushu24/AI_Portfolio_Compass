# P-008：数据页加载延迟与重复账本重放

## 当前进度

用户反馈数据页进入后需等待约 5–10 秒，确认优化方案后授权调整。[C-016](../CODE_CHANGE_LOG/C-016-data-loading-performance.md) 已实现按区域独立展示、按页读取、批量取价、请求内计算复用、精简曲线与按需详情、短期读缓存及写入失效。针对性测试和构建通过；正式服务重载后已核对接口与独立浏览器交互，实际用户验收待完成。

## 目标与方案

- 前端普通读取来自本机 FastAPI/SQLite；不将重复 Excel 解析或券商联网作为本次原因。已定位整组等待、复盘逐成交完整重放、历史点重复携带清仓明细、页签挂载重复请求。
- 现有摊薄成本、现金分红、清仓重置及缺失历史估值的规则保持一致；不改账目、报价或引入每日估值补齐。
- 同一数据库会话复用账本重放，事实 flush、commit、rollback 后失效，不建立跨请求金融结果缓存。历史点不重复复制清仓交易列表，当前及清仓详情仍保留。
- 当前、曲线、记账视图分开返回；曲线点击通过时间、事项、来源账户和记录编号读取确切历史点，同时间多事件不混淆。旧 full 视图兼容保留。
- 页面各区域独立接收结果，按页面职责读取；首页仍需要复盘摘要，但摘要请求不阻塞资产。前端合并同一请求并缓存部分读结果 30 秒，按工作区及完整查询地址隔离；写请求前后失效，旧在途响应不得回填缓存，工作区切换清空。
- 复盘批量取得报价，普通读取只生成临时展示对象；明确刷新及保存意图仍可落库。首次临时复盘可正常保存备注。

## 有限完成条件

| 条件 | 结果 |
|---|---|
| 复盘慢请求不阻塞首页资产显示 | 独立浏览器故意挂起复盘请求，资产先显示，通过 |
| 复盘取价不随成交数逐次重放全账本 | 合成数据验证一次重放；正式读接口已降至亚秒 |
| 精简读取保持账目、收益与确切历史点一致 | 合成测试及真实只读基准核对通过，来源及衍生表摘要未变 |
| 重复导航合并读取，写后失效且工作区隔离 | 前端缓存测试及浏览器导航核对通过 |
| 用户实际体验改善 | 待用户使用验收 |

本机实测不等于所有设备或冷启动性能承诺；暂不引入数据库迁移、每日收益曲线重建或长期持久化缓存。
